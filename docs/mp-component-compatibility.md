## 原生组件覆盖风险清单

以下页面同时含 `canvas` 等原生组件和弹层，是“某些设备弹窗打不开或被遮住”的最高风险区：

- `pages/cinema/detail/index.vue`
- `pages/cinema/index.vue`
- `pages/cinema/circuit/list.vue`
- `pages/order/distribution.vue`

另需单独检查二维码、富文本和网页容器：

- `components/tki-qrcode/tki-qrcode.vue`
- `components/uni-parser/uni-parser.vue`
- `components/uni-parser/libs/trees.vue`
- `pages/public/webview.vue`

如果真机仍出现原生层盖住弹窗，应优先把弹层提升为页面级 `root-portal`；无法跨原生层时，再按微信小程序能力改用原生交互，不为 APP 端增加分支。

## 每台设备的最小验收步骤

1. 连续打开、关闭登录弹窗 3 次，验证遮罩可见、按钮可点、页面不穿透滚动。
2. 在商品规格、优惠券和支付确认三个底部弹层中滚到最底，验证底部按钮不被安全区遮挡。
3. 弹出输入法后打开/关闭底部弹层，验证页面恢复位置且按钮未被键盘覆盖。
4. 在上述 4 个原生组件风险页分别打开页面内弹窗，验证弹层位于原生组件上方。
5. 从“我的”依次进入订单、二维码、兑换券、积分商城、客服，再返回，验证传参和返回栈。
6. 弱网下快速触发两次加载或弹窗，验证没有重复请求、重复跳转或无法关闭状态。

## 发布判定

- 自动门槛：`npm run verify:mp` 通过，旧 `cu-modal`、错误触摸阻止属性、Vue 2 `.sync/$set/$delete` 扫描为 0。
- 设备门槛：至少一台 iPhone 刘海/灵动岛设备、一台主流 Android、一台低端 Android完成上述步骤。
- 未完成真机矩阵前，本表只能标记为“代码兼容完成、真机待验”，不能宣称全设备兼容。
