# TTickets Vue 3 升级与体验优化计划

更新日期：2026-08-10

## 1. 项目结论

- 项目是基于 HBuilder/uni-app 的 Vue 2 老项目，包含约 214 个 Vue 页面或组件、73 个注册路由，并使用 Vuex、旧版 uView、旧路由插件及多套自定义弹窗。
- 主要风险不是单个语法，而是 Vue 2 生命周期与模板写法、CommonJS 浏览器依赖、分页重复触发、路由对象传参、弹窗层级/安全区、旧组件库相互叠加。
- 采用“先运行底座、再公共能力、后页面体验、最后真机矩阵”的顺序。这样每一阶段都能单独构建和回归。

## 2. 已完成

### Vue 3 与构建底座

- 入口升级为 `createSSRApp`，Vuex 升级为 4.x，构建系统迁移到 Vite。
- uni-app 依赖升级到 Vue 3 版本，旧 `uview-ui` 映射替换为 `uview-plus`。
- 增加微信小程序开发/构建脚本以及 Vue 3 兼容扫描脚本；H5 仅保留本地视觉预览能力，不作为发布目标。
- 清理 `beforeDestroy`、`destroyed`、`.sync`、`/deep/`、Vue 原型注入等主要 Vue 2 写法。
- 将支付、权限、微信 SDK、海报和富文本等关键 CommonJS 运行时改为 ESM 兼容方式。

### 路由与传参

- 移除旧 `uni-simple-router` 运行时依赖，使用 uni-app 原生导航封装。
- 从 `pages.json` 自动生成 73 条路由元数据，保留登录鉴权信息。
- 普通参数统一编码；对象参数使用短期令牌传递，避免长 URL、二次 JSON 编码和特殊字符丢失。
- tabBar 页面自动使用 `switchTab`，普通页面按 push/replace/reLaunch 分流。

### 下拉、分页与性能

- 增加统一分页响应归一化、去重合并、防并发请求门、请求竞态保护和防抖工具。
- 已治理电影、影院、卖品、订单、电玩、机台等核心列表。
- 修复电影列表触底时误调用不存在的 `getGoodsList`、卖品页数据初始化为对象、加载状态在请求结束前提前关闭等实际缺陷。

### 弹窗与插件兼容

- 新增 `app-safe-popup`：使用 `root-portal`、固定视口、安全区、最大高度滚动、遮罩关闭、阻止穿透及减少动态效果支持。
- 登录、提示、通用模态框、Picker、Popup Layer、商品弹窗等高频弹层已迁移到统一底座。
- 第二轮继续迁移分享、浮动二维码、SKU、服务保障、拼团、优惠券、影院客服、地址选择和筛选遮罩；源码中不再保留旧 `cu-modal` 模板或错误的 `cathctouchmove/catchtouchmove`。
- 自定义弹层及瀑布流补齐 Vue 3 `modelValue`/`update:modelValue`，同时保留旧 `value`/`input` 事件兼容。
- 微信 SDK 改为浏览器安全的副作用加载方式；删除会导致 H5 空白页的旧 ClipboardJS 全局补丁。
- 保留注意事项：位于 `video`、`map`、`canvas`、`web-view` 等原生组件上方的弹层，仍需在对应微信真机上验证。详细矩阵见 [微信小程序组件兼容矩阵](./mp-component-compatibility.md)。

### 视觉升级

- 建立白色/浅灰背景、橄榄绿主色、圆角、边框、阴影、字体层级和安全区设计变量。
- 已重构电影卡片、活动轮播/卡片、卖品列表、游戏入口、会员头部/钱包/服务列表及登录弹窗。
- 设计概念稿见 [五主页面概念稿](./design/ttickets-vue3-concept.png)。
- “我的”页已按真实功能二次收敛：只呈现账户信息、手机号绑定、四项真实资产与五个已接通服务入口，不照搬概念稿中的会员等级、签到、邀请奖励等未启用功能。实现基准见 [我的页面概念稿](./design/user-center-concept.png)。
- “我的订单”页已按真实接口字段重构电影票/商品双状态：修复商品触底误请求电影接口、重复请求竞态、商品卡误跳电影详情和固定宽度小屏溢出；没有增加搜索、退款筛选或虚构订单状态。实现基准见 [电影票订单概念稿](./design/orders-movie-concept.png) 与 [商品订单概念稿](./design/orders-product-concept.png)。
- 商品订单详情补齐接口返回前与空数组保护，避免弱网设备点击“立即兑换”后因直接访问 `Data[0]` / `Data2[0]` 而白屏。

## 3. 当前验证结果

- `npm run check:vue3`：通过。
- `npm run build:mp-weixin`：通过，输出目录为 `dist/build/mp-weixin`。
- `npm run verify:mp`：通过；该命令串联 Vue 3 扫描、微信小程序构建和发布就绪检查。
- 微信构建产物共 73 个路由，主包约 1.746 MiB，9 个分包均小于 0.5 MiB。
- 已通过本机微信开发者工具 CLI 导入项目；最新本地日志中项目相关 ERROR 为 0，CLI 登录状态为已登录。
- 浏览器仅作为视觉回归代理；发布和功能结论以微信小程序构建、开发者工具与真机为准。

## 4. 下一阶段（发布前必做）

1. 在微信开发者工具导入 `dist/build/mp-weixin`，确认合法域名、隐私接口、分包体积和基础库版本。
2. 使用测试账号跑通：登录 → 选影院 → 电影/场次 → 下单支付，以及卖品、活动、电玩、订单、售后流程。
3. 真机矩阵至少覆盖一台 iPhone 刘海/灵动岛设备、一台主流 Android、一台低端 Android；重点测试键盘顶起、横竖屏、安全区、长列表、连续弹窗和返回手势。
4. 对包含 `video/map/canvas/web-view` 的页面逐个打开弹窗；发现遮挡时改用页面级 popup 或平台原生层。
5. 采集首屏、列表滚动和接口耗时，确定是否继续做图片压缩、分包预加载、接口缓存和骨架屏优化。

真机二维码需要执行微信开发者工具 `preview`，该动作会把临时代码包发送到微信服务；必须在获得明确授权后执行，不等同于正式上传或发布。

## 5. 发布门槛

- Vue 3 检查、微信小程序构建和发布检查全部通过。
- 核心流程无阻断级控制台错误；分页不重复、不丢页；路由返回后状态符合预期。
- 弹窗在测试矩阵中可打开、可关闭、不穿透、不被键盘或安全区遮挡。
- 关键页面与概念稿保持同一视觉语言，同时业务字段、价格、库存和支付行为不被视觉改造改变。
